# WebSocket-контракт

Браузер использует тот же origin: `wss://DOMAIN/ws/documents/{id}`.
Локально используется `ws`. Параметры: `token` — access JWT,
`generation` — целое поколение из REST-метаданных. Заголовок `Origin`
должен точно соответствовать `ALLOWED_ORIGINS`. Query нельзя журналировать.

## Бинарный канал

Применяется y-websocket / y-protocols, не произвольный JSON.
Первый varuint задаёт сообщение: `0` sync, `1` awareness, `3` query awareness.
У sync второй varuint: `0` SyncStep1, `1` SyncStep2, `2` Update.
Далее идёт длина varuint и бинарное содержимое Yjs. Сервер начинает с
SyncStep1; клиент отвечает SyncStep2 и запрашивает состояние сервера.
Общий XML fragment TipTap называется `default`.

Owner/editor передают изменения; viewer получает состояние и отправляет
awareness, но ни SyncStep2, ни Update от него не изменяют документ.
Имена и цвета курсоров не являются удостоверением пользователя.
JWT проверяется при входе, каждом сообщении и периодически.

Лимиты: 10 CRDT-соединений на документ, 50 на API, сообщение 1 MiB,
результирующее состояние 5 MiB. Последнее проверяется на копии до применения.

## Управляющий канал

`/ws/documents/{id}/status?token=...&generation=...` — отдельный канал JSON,
только сервер → клиент. На каждое CRDT-соединение разрешён максимум один
канал статуса того же пользователя, всего не более 50.

```json
{"status":"saved","revision":12,"generation":2}
```

Статусы: `saved` (успешный commit), `unsaved`, `error`.
Изменение роли: `{"status":"role_changed","role":"viewer"}`.
При потере любого нужного соединения интерфейс не показывает «сохранено».

## Закрытие

| Код | Причина |
|---|---|
| 1000 | Корректное завершение |
| 1003 | Неподдерживаемый формат |
| 1009 | Превышение размера |
| 1013 | Продолжительная ошибка сохранения |
| 4401 | Неверный/истёкший JWT |
| 4403 | Отказ в доступе или Origin |
| 4404 | Документ удалён/не найден |
| 4409 | Старое поколение |
| 4429 | Лимит соединений |

При кратком обрыве клиент сохраняет Y.Doc в памяти вкладки и синхронизируется
повторно. При 4409 старый Y.Doc уничтожается, метаданные запрашиваются заново,
создаётся новый редактор. Правки старого поколения не переносятся в новый.
