# Руководство пользователя

Для тех, кто работает с Cowrite в браузере. Установка и запуск — в README.

## Первый вход

1. Откройте адрес приложения (локально — `http://localhost:8080`).
2. Без входа сразу показывается форма. Чтобы создать аккаунт, нажмите
   **«Создать аккаунт»** — появится поле **«Имя»**.
3. Заполните «Имя», «Email» и «Пароль». Пароль — от 12 до 128 символов;
   пробелы внутри пароля значимы, не обрезайте его.
4. Нажмите **«Зарегистрироваться»**. Аккаунт создаётся и сразу выполняется
   вход — повторный пароль вводить не нужно.

Если регистрация прошла, но вход не удался (например, сработал лимит
запросов), форма вернётся в режим входа: введите тот же email и пароль
и нажмите **«Войти»**.

Войти можно и через GitHub кнопкой **«Войти через GitHub»**. Кнопка показана
всегда — интерфейс не проверяет настройки сервера. Если на сервере не заданы
ключи OAuth App, по нажатию откроется страница с ошибкой 503
(`GitHub login is not configured`); локальная регистрация при этом работает
как обычно.

## Список документов

После входа открывается страница **«Документы»**. В шапке кнопка **«Выйти»**.

Каждая строка — название, ваша роль (**Владелец**, **Редактор** или
**Читатель**) и дата изменения. Кнопка **«Удалить»** есть только у владельца
документа; она спрашивает «Удалить «Название»?». Если документов больше 20,
между страницами переключают **«Назад»** и **«Далее»**.

**«Новый документ»** создаёт пустой документ с названием «Без названия» и
сразу открывает его в редакторе.

## Редактор

В шапке: логотип **Cowrite** (возврат к списку), поле с названием и кнопки
панелей **«Доступ»**, **«История»**, **«PDF»**.

Название может менять только владелец — у редактора и читателя поле закрыто
для ввода. Изменение сохраняется, когда вы убираете курсор из поля.

Панель форматирования содержит **Ж** (жирный), **К** (курсив), **H1–H3**
(заголовки), **«• Список»** и **«1. Список»**. У читателя панель скрыта, текст
только для чтения.

Совместное редактирование видно сразу: правки второго человека появляются в
тексте, курсоры подписаны именами. Подпись курсора — это `Участник` и
последние четыре цифры идентификатора клиента (например, «Участник 3f1a»),
её не взять из профиля и нельзя подтвердить; цвет считается из того же
идентификатора. Права определяются ролью в панели «Доступ», а не подписью.

### Статус сохранения

В шапке постоянно показывается состояние:

| Надпись | Что значит |
|---|---|
| «Подключение…» | Соединение с сервером устанавливается |
| «Соединение установлено» | Канал работает, правки передаются |
| «Есть несохранённые изменения» | Правки дошли до сервера, но ещё не записаны в базу (запись происходит через 2 секунды покоя) |
| «Сохранено» | Состояние записано в PostgreSQL |
| «Ошибка сохранения» | Запись не удалась, текст пока только на сервере |
| «Нет соединения» | Канал закрыт, браузер сам переподключается |

При обрыве сети не закрывайте вкладку: набранные правки остаются в памяти
страницы и уходят на сервер после восстановления соединения.

## Общий доступ (только владелец)

1. В редакторе откройте **«Доступ»**.
2. Введите email уже зарегистрированного пользователя, выберите роль
   **«Редактор»** или **«Читатель»**.
3. Нажмите **«Предоставить доступ»**. Появится сообщение «Доступ предоставлен»,
   пользователь добавится в список.

Если вместо этого видно «Доступ предоставлен, письмо не поставлено в очередь»,
права выданы корректно, но фоновая задача не встала в очередь — пользователю
можно сообщить о документе напрямую.

Локально письмо-приглашение уходит не на почту, а в Mailpit:
`http://localhost:8025`. В письме — ссылка на документ.

Убрать доступ — кнопка **«Убрать»**. Активное соединение отозванного
пользователя закрывается, права перестают действовать сразу, не дожидаясь
истечения кэша.

## История и откат

Панель **«История»** показывает снимки состояния: время, источник
(**«Ручная»**, **«Автоматическая»**, **«Экспорт»**) и ревизию.

- **«Сохранить версию»** — снимок текущего состояния. Кнопки нет у читателя.
- **«Восстановить»** — откат к выбранной версии. Спрашивает:
  «Восстановить версию? Текущие соединения будут сброшены,
  несинхронизированные правки потеряются.»

Перед откатом сервер сам делает снимок текущего состояния, так что откат
обратим: к «новому» тексту тоже можно вернуться из истории.

После восстановления остальные открытые вкладки получают сообщение
«Восстановлена другая версия. Редактор будет перезагружен.» и перезагружают
редактор. Незаписанные правки этих вкладок не переносятся — сохраните их
перед откатом.

Автоматические снимки создаются каждые 5 минут, но только для документов,
изменившихся с прошлого раза.

## Экспорт в PDF

1. Откройте **«PDF»**.
2. Нажмите **«Создать PDF»** — появится «Подготовка…».
3. Когда кнопка сменится на **«Скачать PDF»**, нажмите её: файл сохранится
   под названием документа.

Готовность опрашивается каждые 2 секунды, закрывать панель не нужно. Экспорт
не меняет документ: PDF строится из снимка состояния, сделанного в момент
заказа. Если вместо файла появилась надпись «Не удалось создать PDF», задача
завершилась ошибкой — попробуйте создать PDF ещё раз.

Скачанный файл доступен 24 часа, потом удаляется.

## Возможные сообщения

| Сообщение | Причина и что делать |
|---|---|
| «Не удалось войти» | `Invalid email or password` — сервер возвращает ошибку на английском. Отдельного ответа «такого пользователя нет» нет намеренно |
| «Доступ закрыт» | Права отобрали, пока вкладка была открыта. Вернитесь **«К документам»** |
| «Документ удалён» | Владелец удалил документ. Вернитесь **«К документам»** |
| «Страница не найдена» | В адресе нет пути из списка (например, опечатка). Ссылка **«Открыть редактор»** ведёт к списку документов |
| «Слишком много запросов» | Превышен лимит на IP. Подождите и повторите |
| «Не удалось войти» + «Повторить» | Сбой входа через GitHub. «Повторить» начинает заново |

## Про перезагрузку страницы

Токен доступа хранится только в памяти вкладки и не пишется в диск или
хранилище браузера. После F5 нужен повторный вход, но **адрес открытого
документа сохраняется**: после входа вы вернётесь в тот же документ, а не
в список.
